# Batch-rename-files
文件批量重命名工具——
基于 .NET Framework 4.8 + WinForms，单个 exe，无第三方依赖，无需安装。
---

## 功能

### 功能一：添加排序序号

按文件列表当前顺序，给每个文件名加一个递增序号。

| 选项 | 说明 |
| --- | --- |
| 起始序号 | 从第几个号开始，默认 `1` |
| 序号位数 | 不足位数补 `0`，默认 `4` 位（`0001`） |
| 递增步长 | 每个文件递增多少，默认 `1` |
| 连接符 | 序号和原名之间的分隔串，默认 `" - "` |
| 加在开头 / 加在末尾 | 序号放前面还是后面 |
| 先去掉原有的序号开头 | 命中 `001_`、`01-`、`3.` 这类旧前缀时先剥掉，避免 `0001 - 01 - 报告.txt` 这种叠加 |

### 功能二：部分字段替换重命名

对文件名主体（不含扩展名）做查找替换，支持普通文本和正则表达式两种模式。

### 安全机制

- **实时预览**：改动任意规则后自动重算「新文件名」列，不需要手动点按钮
- **冲突检测**：同目录下新名重复、或与列表外的磁盘文件撞名，相关行**加粗标红**，并且「执行重命名」按钮直接禁用
- **两阶段改名**：先在原目录改到临时名，再改到目标名，因此列表内两个文件互换名字也不会互相覆盖
- **执行前二次确认**：弹窗告知本次会改多少个文件

### 界面

- 拖拽文件 / 文件夹进窗口即可添加（受「包含子文件夹」开关影响）
- 列表按文件名 / 大小 / 修改时间点击列头排序，可筛选
- 支持 10 万+ 文件（`ListView` 虚拟模式），不卡顿
- 高 DPI 友好（已在 175% 缩放下验证）

## 系统要求

- Windows 7 SP1 / 8.1 / 10 / 11
- .NET Framework 4.8（Win10 1903+ 与 Win11 已内置，无需单独安装）

---

## 使用

直接双击 `FileRenamer.exe`。

1. 点「添加文件…」「添加文件夹…」，或把文件/文件夹拖进窗口
2. 勾选要用的功能并填好参数，右侧「新文件名（预览）」列会实时刷新
3. 确认没有标红行，点「执行重命名」
4. 弹窗确认后执行，底部状态栏显示成功 / 失败数量；有失败会列出明细

> 序号是按列表**当前显示顺序**分配的，所以先排序（点列头）再执行，可以控制编号顺序。

## 从源码构建

### 方式一：.NET SDK（推荐）

```powershell
dotnet build FileRenamer\FileRenamer.csproj -c Release
```

产物：`FileRenamer\bin\Release\net48\FileRenamer.exe`

需要 [.NET SDK](https://dotnet.microsoft.com/download)（任意 6.0+ 版本即可，项目自带 `Microsoft.NETFramework.ReferenceAssemblies.net48` 引用程序集，不要求本机装 Visual Studio）。

### 方式二：`构建.ps1`

仓库根目录的 `构建.ps1` 是一个不依赖 NuGet 的备用编译脚本，直接调用 SDK 自带的 Roslyn 编译器：

```powershell
powershell -ExecutionPolicy Bypass -File .\构建.ps1
```

产物：根目录的 `FileRenamer.exe`，并同步一份到 `FileRenamer\bin\`。

> 这个脚本是为「NuGet 恢复被环境策略挡住」的场景准备的（例如受限沙箱里 `dotnet build` 无法写 `%LOCALAPPDATA%\NuGet`）。普通开发机用方式一就行。

### 方式三：Visual Studio

用 VS 2019/2022 直接打开 `FileRenamer\FileRenamer.csproj`（无需 .sln）。
